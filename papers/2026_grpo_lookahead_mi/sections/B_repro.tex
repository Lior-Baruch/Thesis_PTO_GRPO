\section{Reproducibility details}
\label{app:repro}

\subsection{Configuration}

Both arms are launched from the same notebook with the same cell-1 configuration block; the arm
identity is encoded in the experiment name, which also determines the output directory, so two
arms can never share a folder. The tracked \texttt{run\_metadata.json} of each arm records the full
resolved configuration. Diffing the two files yields exactly two substantive differences
($\texttt{lookahead\_k}$: absent vs.\ 5; $\texttt{lookahead\_sub\_batch\_size}$: absent vs.\ 128)
plus the arm's own name, adapter repository, and two output paths.

\subsection{Anti-degeneracy}

The base 1B model will occasionally continue past its own turn and write the patient's reply. All
decode sites stop at the chat-template markers and truncate any completion at the first such
marker; a completion that is empty after cleaning ends the conversation, and a degenerate
completion is floored to the minimum reward. This applies identically in both arms, including
inside the $K{=}5$ rollout.

\subsection{Evaluation and statistics}

Model states are scored offline into a partitioned score archive keyed by
grader $\times$ replicate $\times$ instrument $\times$ training-oracle $\times$ model, one record
per conversation, so a grader is an ordinary partition key rather than a privileged path and an
interrupted scoring run resumes by skipping completed work. The reported draw is replicate 0 for
each grader.

All contrasts are persona-paired. The 96 personas are reshuffled every iteration, so pairing
recovers the persona identity by replaying the shuffle --- pairing on file order would join
unrelated conversations across iterations and is the single easiest way to get these numbers
wrong. Tests are Wilcoxon signed-rank; effect sizes are Cohen's \dz; intervals are 2{,}000-resample
percentile bootstraps at a fixed seed, so a re-render reproduces the same bounds. Holm correction
is applied within each family (instruments within one matched contrast, or iterations within one
sweep) and is not pooled across families.

\subsection{Compute accounting}

Per-iteration GPU-hours are reconstructed from the modification times of per-step training
artifacts, since the metadata's elapsed-time fields are per-process and undercount resumed
iterations --- in the worst case in this experiment by nearly $2\times$. An inter-step gap outside
$(0, 3600\,\mathrm{s})$ is treated as a resume gap or a re-synced timestamp and imputed at the
phase median, so the step is counted once; the number of imputations is recorded per arm. An
iteration is billed as generation plus training. Budget-matched comparisons pair \emph{different}
iterations across arms, which is why every such comparison pairs on persona identity rather than
file order.

\subsection{Artifacts}

Every number in this paper is traceable to a tracked table under
\texttt{Exp3\_PTO\_GRPO/eda/results/}, and the mapping from claim to table is the paper's
\texttt{NUMBERS.md} ledger. Figures are copied from that same tree by \texttt{sync\_figures.py}
rather than regenerated here, so the draft compiles standalone and a submitted PDF is frozen
against later re-renders.
