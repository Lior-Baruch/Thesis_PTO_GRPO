- **budget_sweep_gpt4m** -- Budget sweep on Q1Q2, grader gpt4m: solid = each arm's BEST checkpoint within the budget (ranked on sign_of(metric) * score), dashed = its LAST checkpoint within the budget, which is what a fixed-endpoint reading quotes. Where the two separate, the arm peaked and then regressed, and the endpoint reading reports the wrong number. Arms of one setting only.
- **budget_sweep_gpt4m_ThL1B** -- No budget sweep for grader gpt4m, ThL1B.
- **compute_trajectory** -- Cumulative GPU-hours (trainer session log, summed over sessions) needed to produce each model state, per arm. A steeper line is a more expensive iteration; the same x position on two lines is the same iteration index but NOT the same price, which is the whole reason this family exists.
- **cost_benefit_gpt4m** -- Mean Q1Q2 (across the personas scored) against the cumulative GPU-hours that produced each model state, grader gpt4m; markers are annotated with the state index. Cost comes from the trainer's session log, never from file mtimes. Read the lever off the whole curve: which arm is ahead is a function of budget.
- **cost_breakdown** -- Total GPU-hours per arm split by trainer phase. `build` is PTO's preference construction and is structurally absent for GRPO, which computes its reward inside the training loop -- so a per-step comparison between the two methods is not a comparison of what they cost.
